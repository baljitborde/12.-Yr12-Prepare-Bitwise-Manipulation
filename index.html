What is Bitwise Manipulation?
● ~10 minutes

Bitwise manipulation means working on the individual bits of a binary pattern rather than on the number as a whole. There are two families of operation in this topic:

⇆ Shifts

Move every bit a set number of places to the left or right. Used for fast multiplication and division by powers of 2, and for moving bits into position. Two types: logical and arithmetic.

🎭 Bit masks

Combine a pattern with a second pattern called a mask, using AND, OR or XOR, to check, clear, set or flip chosen bits while leaving the others alone.

Naming the bits
Bit number76543210
Place value1286432168421
Example10110010

The left-most bit (bit 7) is the most significant bit (MSB); the right-most bit (bit 0) is the least significant bit (LSB). On this page bits are numbered from 0 on the right.

Why is bitwise manipulation needed?
  • Speed: shifts and logic operations are among the fastest instructions a CPU can carry out — a shift is much quicker than a general multiplication or division.
  • Saving space: one byte can hold eight separate on/off settings called flags (e.g. the CPU's status register, or which buttons on a game controller are pressed).
  • Talking to hardware: device drivers read and write single bits in hardware registers to switch features on or off.
  • Everyday uses: network subnet masks, file permissions, graphics and colour processing, and simple encryption.
Specification 2.2.2: You need to know the definition, function, characteristics, why needed and operation of logical shifts, arithmetic shifts and bit masks (AND, OR, XOR), and be able to perform binary shifts and use a mask to check the status of bits in a binary pattern.

Logical Shifts
● ~18 minutes

In a logical shift, every bit moves the same number of places left or right. The bit that falls off the end is lost (in a real CPU it usually goes into the carry flag), and the empty space at the other end is always filled with 0. A logical shift treats the pattern as an unsigned binary number.

Logical shift LEFT by 1
Before (22)00010110
After (44)00101100

Left-most bit lost (red), 0 enters on the right (orange). Value doubles.

Logical shift RIGHT by 1
Before (22)00010110
After (11)00001011

Right-most bit lost, 0 enters on the left. Value halves.

ShiftEffect on an unsigned valueExample
Left by n placesMultiplies by 2nLeft 3 = × 8
Right by n placesDivides by 2n, throwing away any remainderRight 2 = ÷ 4
Overflow: if a 1 is shifted out of the left, the answer is too big for the bits available and the result is wrong. 200 shifted left should be 400, but 400 needs 9 bits.
Loss of precision: if a 1 is shifted out of the right, the remainder is lost. 13 shifted right by 1 gives 6, not 6.5.

3
Arithmetic Shifts
● ~17 minutes

An arithmetic shift is used on signed numbers stored in two's complement. Quick reminder: in 8-bit two's complement the MSB has a place value of −128, so the MSB acts as the sign bit — 0 means positive, 1 means negative.

−1286432168421Value
11101000−128 + 64 + 32 + 8 = −24

The problem: if we logically shift −24 right, a 0 enters the sign bit and the number suddenly becomes positive. An arithmetic shift right fixes this by copying the sign bit into the MSB instead of inserting 0.

✗ Logical shift right by 1
Before (−24)11101000
After (+116)01110100

The sign is lost — the answer is wrong.

✓ Arithmetic shift right by 1
Before (−24)11101000
After (−12)11110100

The sign bit (purple) is copied in, so −24 ÷ 2 = −12 ✓

Arithmetic shift right
Bits move right; the sign bit is copied into the MSB each time. Divides a signed number by 2n and keeps its sign. Positive numbers have a sign bit of 0, so 0s enter — the same as a logical shift.
Arithmetic shift left
Bits move left and 0s enter on the right — the same as a logical shift left. It multiplies by 2n. If the sign bit changes, the result has overflowed and is wrong.
Which shift? Use a logical shift for unsigned numbers and for moving bits around in a pattern. Use an arithmetic shift when the pattern is a signed two's complement number and you need to keep its sign.

AND Masks: Checking and Clearing Bits
● ~15 minutes

A bit mask is a binary pattern that is combined with another pattern bit by bit: bit 7 with bit 7, bit 6 with bit 6, and so on. The logic operation decides what happens to each bit.

BitMaskAND
000
010
100
111

AND gives 1 only when both bits are 1. So:

  • A 1 in the mask keeps the original bit.
  • A 0 in the mask clears the bit to 0.

That makes AND perfect for checking one bit or clearing (switching off) bits.

Using a mask to check the status of a bit

Is bit 5 of 10110010 set to 1? Make a mask with a 1 only in bit 5, and AND it with the pattern:

Pattern10110010
Mask (AND)00100000
Result00100000

Every other bit is cleared to 0. If the result is not zero, the bit was 1; if the result is 00000000, the bit was 0. Here the result is 00100000, so bit 5 is set.

Real use: a network subnet mask such as 255.255.255.0 is ANDed with an IP address to keep the network part of the address and clear the host part.

Useful XOR facts: XOR with 11111111 flips every bit. XOR with the same mask twice gets you back to the original pattern — the idea behind simple XOR encryption. XORing a value with itself always gives 0, so XOR can check whether two patterns are identical.

✓ Summary — Topic 2.2.2: Bitwise Manipulation
Why needed: bitwise operations are very fast, let one byte hold eight flags, and let programs control hardware and individual settings.
Logical shift: all bits move; the bit shifted out is lost and 0s fill the gap. Left n = × 2n, right n = ÷ 2n for unsigned numbers. Watch for overflow and lost precision.
Arithmetic shift: for signed two's complement numbers. Right shift copies the sign bit into the MSB to keep the sign; left shift fills with 0s, and a change in the sign bit means overflow.
AND mask: 1 keeps, 0 clears. Used to check a bit (non-zero result = bit is 1) or to clear bits.
OR mask: 1 sets the bit to 1, 0 keeps it. Used to switch flags on.
XOR mask: 1 flips the bit, 0 keeps it. Applying the same XOR mask twice restores the original.
